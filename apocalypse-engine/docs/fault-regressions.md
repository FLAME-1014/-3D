# 故障回归

每个按钮都执行一对独立实验：先在临时子系统实例中开启对应缺陷，再关闭注入并从相同种子重建。两次使用同一个检测条件；只有第一次失败且第二次通过才算回归通过。`reports/fault-regressions.json` 中的 `injected` 和 `repaired` 保存两次实际观测。例如，跳过物理世界恢复后，时钟可以完全一致，但刚体高度仍有偏差。

通过 `npm test` 运行八个 Vitest 故障回归；开发服务器附加 `?faults=1` 可逐个复现真实模拟子系统。除帧循环和事件清理外，每项在独立 Rapier 世界和 `Simulation` 上执行，并在断言结束后释放模拟资源。

| 故障 | 可复现条件 | 根因检查 | 回归验证 |
|---|---|---|---|
| 物理对象释放不完整 | 坍塌一栋楼后重建 Rapier 世界 | 建筑刚体应被删，动态目录和碰撞体应重建到基线 | 检查初始刚体、碰撞体、系绳与动态对象数 |
| 暂停后物理仍在运行 | 预警后暂停并推进墙钟一秒 | `clock.time` 与 `physics.steps` 必须保持原值 | 验证冻结；再验证单步只前进 1/60 秒 |
| 洪水重置后水位未恢复 | 把初始水位设为 5 m，再点重置 | metrics、设置、网格边界与 store 读数 | 重置后逐一相等并等于规范默认值 |
| 灾害切换残留旧事件 | 台风过预警期后切换地震 | 上一灾害的雨量、风速、地震包络必须清零 | 保留台风影响证据后验证新情景输入清零 |
| 重复开始动画循环 | 同一代次两次启动并显式执行失效回调 | 调度器只应产生一个请求，stop 应清除旧请求 | 检查请求数、RAF 表和过期回调不变量 |
| 损伤统计与楼体不同步 | 设置单栋受损状态并派生实时指标 | 结构图、损伤数与受影响数同源 | 从结构 Map 派生并比较枚举状态及损伤值 |
| 检查点反复恢复漂移 | 活动洪水模拟中保存，推进后恢复两次 | 比较时钟、Rapier 数量、完整浅水网格和所有刚体坐标 | 两次恢复与未变更的初始捕获逐项一致 |
| 场景销毁后监听器残留 | 绑定、派发、双重销毁、再次派发 | dispose 后监听回调总计不再增长 | 使用真实 `EventTarget` 和 `DisplayBindings` 断言 |
