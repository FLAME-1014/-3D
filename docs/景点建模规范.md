# 景点建模规范 v0.1

> 适用：Canton Atlas 的“单体景点 3D 模型”内容生产。  
> 目标：把“凭感觉建模”改成“按数据卡建模、按评分卡验收”。  
> 非目标：城市级连续 3D、测绘级还原、写实渲染。

---

## 0. 一句话流程

**来源 → 数据卡 → 体块 → 标志性细节 → 材质/灯光 → 交互 → 评分卡 → 入图鉴。**

每个阶段不通过，不进入下一阶段。

---

## 1. 核心原则

1. **规格驱动**：先填 `spot.json`，再写模型；不要先写代码再补理由。
2. **来源可追溯**：每个尺寸、事实、参考图，都要有来源和可信度。
3. **风格化优先**：不追写实；轮廓 + 比例 + 2–3 个标志性细节，比堆装饰有效。
4. **识别优先**：3 秒认不出，细节再多也不算完成。
5. **统一优先**：同一批模型放在一起，必须像同一个产品。
6. **不假装精确**：不确定就标 `C`，不要把估算写成事实。
7. **可回收**：模型必须能 `dispose()`，不泄漏 GPU 资源。

## 2. 数据来源与来源账本

### 2.1 来源分级

| 级别 | 来源 | 用来确定 | 可信度 |
|---|---|---|---|
| **A 官方** | 场馆官网、广州市/广东省文物局、规划和自然资源局、地方志、正式图纸、学术论文 | 年代、功能、尺寸、开放信息 | 高 |
| **B 开放数据** | OSM（轮廓/高度）、卫星影像、Microsoft/Google 建筑轮廓、天地图 | 平面轮廓、朝向、大致高度 | 中 |
| **C 图像** | 官方照片、Wikimedia Commons、Flickr CC、明信片、街景 | 比例、材质、细节、屋顶形式 | 中 |
| **D 二手** | 百科、攻略、小红书、旅游文章 | 氛围、看点、故事 | 低，只做线索 |

**规则：**

- 尺寸只认 A/B；C 只用来校正比例；D 不作为尺寸依据。
- 每个景点必须有 `sources[]`，字段见 2.3。
- A/B 来源未 `verified: true` 时，景点不能进入 `review`。
- 图片只做参考，不直接当贴图；要用图，必须记录作者和许可。
- 不确定就标 `confidence: "C"`，并在 `note` 里写清楚。

### 2.2 广州常用来源

| 来源 | 用途 | 备注 |
|---|---|---|
| [OpenStreetMap](https://www.openstreetmap.org/) | 建筑轮廓、道路、朝向 | 记录具体 way ID；数据可能滞后 |
| [Wikimedia Commons](https://commons.wikimedia.org/) | 照片参考 | 逐图核对作者与许可 |
| [高德开放平台](https://lbs.amap.com/) | POI、坐标、周边 | 注意 GCJ-02 与 WGS84 的差异 |
| [天地图](https://www.tianditu.gov.cn/) | 底图、影像 | 注意使用条款 |
| 场馆官网 | 年代、沿革、开放信息 | 优先 A 级 |
| 广州市规划和自然资源局 | 规划、测绘、公开数据 | 以官网公开为准 |
| 广东省文物局 / 广州市文化广电旅游局 | 文物保护单位信息 | 以官网公开为准 |
| 广州市地方志 | 历史沿革、尺度 | 以公开版本为准 |
| 学术论文（知网/万方等） | 尺度、历史、形制 | 记录篇名、作者、年份 |
| 卫星影像 | 屋顶形式、平面轮廓 | 与 OSM 交叉验证 |

### 2.3 来源记录字段

```json
{
  "type": "official | osm | satellite | photo | academic | project | secondary",
  "title": "来源标题",
  "url": "https://...",
  "author": "作者/机构",
  "license": "ODbL / CC BY-SA / 官方公开 / ...",
  "accessed": "YYYY-MM-DD",
  "confidence": "A | B | C | D",
  "verified": false,
  "note": "这条来源支持了哪个字段"
}
```

### 2.4 尺寸口径

- `1 单位 = 1 米`；Y 轴向上；原点在**底面中心**；北 = `-Z`（与 `fusion-geo.js` 的 +Z 向南一致）。
- 优先用 OSM 轮廓 + 卫星影像定平面；没有测绘数据时，用照片估比例，但必须标 `C`。
- 记录：`siteAreaM2`、`buildingAreaM2`、`footprintM`、`heightM`、`floors`，每项都给 `confidence`。
- 不要混用 WGS84 / GCJ-02；需要时两者都存，并注明用途。
- 未核对的长宽高保持 `null`，不要填一个“看起来差不多”的数。

### 2.5 AI 的边界

**可以做：**

- 检索线索、找官方页面、做摘要和翻译；
- 生成代码骨架、占位纹理、验收脚本；
- 对比截图、提出修改建议。

**不可以做：**

- 提供尺寸、年代、许可结论；
- 直接把网络图片当贴图；
- 代替人工核对；
- 用“大概/可能”生成事实。

> AI 是助手，不是来源。每条事实都要能点回原文。

## 4. 数据卡 `spot.json`

字段说明：

| 字段 | 说明 |
|---|---|
| `schemaVersion` | 规范版本，当前 `0.1` |
| `id` | 目录名/路由名，小写英文 |
| `name` | 展示名 |
| `status` | `draft` → `review` → `pass` → `published` |
| `geo` | WGS84/GCJ-02 坐标、锚点说明、北向 |
| `dimensions` | 面积、长宽、高度、层数、可信度、备注 |
| `features` | 标志性特征；`priority: 1` 是识别必需 |
| `style` | 美术方向、灯光、展台、色板、背景、时间 |
| `presets` | 机位名：`overview` / `front` / `detail` / `street` / `arcade` / `gate` / `stage` / `avenue` / `church` / `hotel` / `park` / `ancient-road` / `temple` / `wuyang` / `wall` / `zhenhai` / `canal` / `bridge` / `tower` / `house` / `opera` / `qilou` / `taotao` / `lianxiang` / `paifang` / `summit` / `base` / `lattice` / `top` / `river` / `facade` / `rose` / `side` / `apse` / `box` / `plaza` / `pool` / `mouth` / 自定义 |
| `presetOverrides` | 可选：按景点覆盖机位的 `yaw` / `pitch` / `distance` / `target` |
| `hotspots` | 热点；`anchor` 指向模型模块暴露的锚点 ID |
| `hotspotMode` | 可选：`"preset"` 时总览显示全部热点，进入非总览机位后只显示与该机位同名的热点 |
| `model` | 模型模块路径、单位、上方向、原点 |
| `sources` | 来源账本 |
| `acceptance` | 验收级别（`tier`）、状态、分数、检查项 |
| `notes` | 决策记录 |

`acceptance.tier`：`A` = 首发/旗舰，5 人识别；`B` = 批量/迭代，1–2 人 lite；`C` = 草稿，不做识别测试。

### 4.1 `features`

- `priority: 1`：没有它，3 秒识别会失败（最多 3 个）。
- `priority: 2`：支撑性细节。
- `priority: 3`：可选装饰，时间不够可砍。

### 4.2 `presets`

用语义名，不写死坐标。场景模板根据模型包围盒自动构图：

- `overview`：3/4 俯视总览；
- `front`：正立面；
- `detail`：标志性细节特写；
- `courtyard` / `night` / `street` / `arcade` / `gate` / `stage` / `paifang` / `summit` / `base` / `lattice` / `top` / `river` / `facade` / `rose` / `side` / `apse`：按景点类型自定义。

需要时可在 `presetOverrides` 里按机位覆盖 `yaw` / `pitch` / `distance` / `target`；`distance` 用米，模板会在移动端乘以 `aspectFactor`。  
默认相机最近距离是 `maxDim * 0.28`；需要更近的细节机位时，在 `model.zoom` 里写 `{ "min": 4, "max": 260 }` 覆盖。

### 4.3 `hotspots`

- `anchor` 是模型模块暴露的锚点 ID，不在 JSON 里写死坐标。
- `type`：`info`（讲解）、`scene`（跳转）、`link`（外部）。
- 每个景点 3–5 个，先保证不重叠；遗址序列类景点可到 6 个。
- 可选 `hotspotMode: "preset"`：总览显示全部热点；进入非总览机位后，只保留 `preset` 与当前机位同名的热点，其余淡出并停止点击。用于细节机位（如浮雕特写）不被其他标签遮挡。未设置时所有热点始终显示。
- 热点标签会被限制在视口内 8px；移动端依赖这条规则避免贴边裁切。

## 5. 模型模块契约

`content/spots/<id>/model.js`：

```js
export function create() {
  const group = new THREE.Group();

  // 建模型：只做几何、材质、贴图
  // 不要写相机、灯光、UI、控制器

  const anchors = {
    roof_figures: new THREE.Vector3(0, 14, 0),
    wood_screens: new THREE.Vector3(0, 6, 18),
    courtyard: new THREE.Vector3(0, 0, 0)
  };

  return {
    group,
    anchors,
    dispose() {
      group.traverse((obj) => {
        if (obj.geometry) obj.geometry.dispose();
        if (obj.material) {
          const mats = Array.isArray(obj.material) ? obj.material : [obj.material];
          mats.forEach((m) => {
            Object.values(m).forEach((v) => {
              if (v && v.isTexture) v.dispose();
            });
            m.dispose();
          });
        }
      });
    }
  };
}
```

**约定：**

- `1 单位 = 1 米`；Y 向上；原点在底面中心；北 = `-Z`。
- 只导出 `create()`；不写全局状态、不写相机/灯光/UI。
- 材质从共享色板取；不要各自调一套。
- 贴图最大 2K；优先程序化或生成纹理；外部贴图必须有许可。
- 三角形 2–10 万；draw calls < 100。
- 给关键对象起名，方便调试和热点锚定。
- `dispose()` 必须释放 geometry / material / texture。

## 6. 场景模板职责

`web/spot.html` + `js/diorama.js` 负责所有“共用”的东西：

- renderer、色彩空间、色调映射；
- 相机、轨道控制、缩放边界；
- 三点布光（key/fill/rim）+ 环境光；
- 展台、背景、雾；
- 加载模型模块，计算包围盒，自动构图；
- 机位切换、热点投影、遮挡处理；
- 信息面板、打卡、返回图鉴；
- 设备分档、窗口 resize、页面隐藏时暂停；
- 路由切换时 `dispose()`。

模型模块只负责“这件展品长什么样”，模板负责“怎么展示、怎么交互”。

## 7. 建模流程（7 步）

1. **收资料**：3–5 张照片 + OSM 轮廓 + 官方事实；填 `sources`。
2. **填数据卡**：尺寸、层数、屋顶、3 个标志性特征、机位、热点。
3. **体块**：只做轮廓和比例；过“轮廓叠图/比例检查”。
4. **标志性细节**：只做最能被认出的 2–3 处；过“3 秒识别”。
5. **材质与灯光**：统一色板 + 展台；过“风格一致”。
6. **交互**：机位、热点、面板、打卡、返回。
7. **验收**：跑评分卡；≥ 80 才进图鉴。

## 8. 验收

### 8.0 验收分级

| 级别 | 适用 | 必做 | 识别测试 |
|---|---|---|---|
| **A 首发 / 旗舰 / 新类型** | 第一个样板、参赛/发布、全新地标类型 | 轮廓叠图、比例、来源、性能、交互 | **5 人**，≥ 4/5 |
| **B 批量 / 迭代** | 同类型新增、普通更新 | 自动检查、风格拼图、1–2 人 lite | **2 人**，2/2 通过；1/2 升级到 A；每 5 个抽 1 个做 5 人 |
| **C 草稿** | 内部预览、未准备验收 | 页面能开、交互不崩 | 不做 |

**5 人测试只在以下情况做：**

- 新地标类型或首个样板；
- 轮廓、材质、颜色、构图发生大改；
- 准备发布、参赛、对外展示；
- B 级批量里每 5 个抽 1 个做抽样。

**纯代码、性能、热点、交互更新不做识别测试**，只跑固定机位截图回归。  
记录测试级别和样本量，不要把 2 人 lite 写成“5 人通过”。

**B 级通过线**：来源 + 风格 + 性能 + 交互 + 识别 lite。  
`silhouette / proportion / scale` 只在 A 级或抽检时要求；B 级记 `null`，不要记 `false`。

### 8.1 硬检查

| 检查 | 方法 | 通过线 |
|---|---|---|
| 轮廓 | 同机位平色渲染，半透明叠参考图 | 偏差 < 包围盒 10% |
| 比例 | 高/宽比、层数、屋顶坡度对参考 | 误差 < 5% |
| 尺度 | 底面轮廓对 OSM/卫星 | 面积误差 < 10% |
| 性能 | 三角形、draw calls、首屏、帧率 | 见第 9 节 |
| 交互 | 热点锚点、机位、`dispose()` | 不漂、不穿模、无泄漏 |
| 工程 | 控制台、404、JSON、来源 | 无错误、字段完整 |
| 来源 | A/B 来源 `verified` | `review` 前必须为 true |

### 8.2 人工评审

1. **3 秒识别**：截图给 5 个人看，问“这是广州哪里？”  
   - 地标级：≥ 4/5；普通点：≥ 3/5。
2. **风格一致性**：5 个模型同机位、同灯光拼成一张图；陌生人应说“同一套”。
3. **内容准确性**：每条事实能点回来源；没有“好像/大概”的断言。

### 8.3 评分卡

| 项 | 权重 | 通过线 |
|---|---|---|
| 识别度 | 30 | ≥ 24 |
| 比例与尺度 | 20 | ≥ 16 |
| 标志性细节 | 20 | ≥ 14 |
| 风格一致 | 15 | ≥ 12 |
| 性能 | 10 | ≥ 8 |
| 来源完整 | 5 | 5 |
| **合计** | 100 | **≥ 80** |

### 8.4 DoD 清单

- [ ] `spot.json` 字段完整
- [ ] A/B 来源已核对，`verified: true`
- [ ] 尺寸/可信度已填，未核对的保持 `null`
- [ ] 3 个 `priority: 1` 特征已实现
- [ ] 识别测试按 `acceptance.tier` 执行（A 级 5 人；B 级 1–2 人 lite + 每 5 个抽 1 个 5 人；C 级不做）
- [ ] 3 个机位可用
- [ ] 3–5 个热点已锚定
- [ ] `dispose()` 已验证
- [ ] 手机端已测
- [ ] 截图和评分已归档
- [ ] 评分 ≥ 80
- [ ] 页面标注“风格化示意 / 非测绘”
- [ ] 图鉴入口、去过状态已接

## 9. 性能预算

| 项 | 目标 |
|---|---|
| 单景点三角形 | 2–10 万 |
| draw calls | 样板 ≤ 400；优化目标 < 100（合并/实例化） |
| 贴图 | ≤ 2K/张，优先 KTX2/WebP |
| 首屏可交互 | < 3 秒（4G） |
| 桌面帧率 | 60fps |
| 中端手机 | ≥ 30fps |
| 内存 | 切换景点后回落，无明显增长 |

> 陈家祠样板实测：350 calls / 10,054 tris / 1.9 ms per frame（桌面软件渲染测试，`__SPOT_API__.bench(90)`）。视觉优先，后续用几何合并/实例化把 calls 降下来。

## 10. 美术方向：博物馆展柜 / 收藏模型

- **背景**：暖灰/纸色，干净，不抢模型。
- **展台**：每个景点一个底座，像博物馆展品。
- **灯光**：柔和三点光；不要强烈霓虹（除非该景点单独做夜景模式）。
- **色板**：4–6 色，全项目共享；每个景点只做少量偏移。
- **材质**：偏哑光；金属/玻璃才给高光。
- **构图**：3/4 俯视总览、正立面、细节特写。
- **后期**：轻微 AO/暗角；不要重 bloom。
- **定位**：这是“收藏模型”，不是“游戏关卡”。

可选：广州塔、珠江新城单独提供 `night` 模式；其他景点保持统一棚拍。

## 11. 常见失败模式

| 失败模式 | 后果 | 修正 |
|---|---|---|
| AI 找几张图就开写 | 比例漂移、细节臆造 | 先填数据卡，A/B 来源核对 |
| 每个场景一套代码 | 风格不统一、维护爆炸 | 一个 `spot.html` + 模型模块 |
| 只凭感觉调 | 永远不知道是否完成 | 评分卡 + DoD |
| 追写实 | 成本失控、效果仍不够 | 风格化 + 标志性细节 |
| 把所有装饰都做上 | 重点消失、性能下降 | 只做 `priority: 1` |
| 忘记 `dispose` | GPU 内存增长 | 切场景必测 |
| 不标“示意” | 误导用户 | 页面固定标注 |

## 12. 试点计划

第一个样板：**陈家祠**。

理由：非夜景、装饰密集、院落布局明确，能检验“博物馆展柜”风格是否能统一，也能检验代码建模能否表达屋脊陶塑、木雕屏门、青云巷。

两周节奏：

| 时间 | 任务 |
|---|---|
| 第 1–2 天 | 收资料、填 `spot.json`、核对 A/B 来源 |
| 第 3–4 天 | 体块 + 轮廓/比例检查 |
| 第 5–7 天 | 3 个标志性特征 + 3 秒识别 |
| 第 8–9 天 | 材质/灯光/展台 + 风格一致 |
| 第 10–11 天 | 机位/热点/面板/打卡 |
| 第 12–14 天 | 评分卡、修整、入图鉴 |

试点通过后，再按模板迁移 4 个点（沙面、永庆坊、广州塔、广东省博物馆）。
