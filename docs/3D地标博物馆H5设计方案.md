# 广州立体志 · 3D 地标博物馆 H5 设计方案

> 版本：0.1（方案稿）
>
> 日期：2026-11-06
>
> 目标：将已有 18 个单体地标模型，组织成可分享、可浏览、可收藏的移动端数字展览。

## 一、设计判断

建议把项目定位为 **“广州立体志：一座可以旋转阅读的城市模型博物馆”**。它是独立的文化展示 H5，入口、内容组织和用户旅程都围绕模型展览，不再把地图作为主要界面。

已有模型的优势在于每件展品都有自己的观察机位和细节热点。首页不必用一个同时装下全部模型的 3D 大场景；用精致的展览序厅、模型预览图和主题策展来呈现全部展品，点进单件时再打开原有统一 3D 展柜。这样既突出模型，也能把加载压力控制在当前展品。

**核心体验承诺：**打开 H5，先被一件广州地标吸引；进入后能用手指转动、切换机位、点开观察点；离开展品时得到一张带个人印记的收藏卡。

## 二、产品边界与命名

- 暂定主标题：**广州立体志**
- 英文副标：**CANTON ATLAS · A CITY IN MINIATURE**
- 首页主文案方向：**把广州，翻成立体的一页。**
- 内容边界：18 件现有模型、模型观察点和城市文化短文；不提供地图导航、真实步行路线、距离计算或地理比例关系。
- 页面固定说明：**风格化模型，仅用于文化展示；模型范围、比例和细节不代表测绘成果。**
- 所有历史、尺寸、年代和开放信息只从已核实来源卡中选择；未核实值不作为确定事实展示。模型示意说明放在事实标签旁，用户可以轻松查看来源。

## 三、信息架构

| 页面 | 目的 | 主要内容 |
|---|---|---|
| 展览序厅 | 建立气质、开始浏览 | 一件当期主展品、展览主题、入馆按钮、浏览全部展品 |
| 展品长廊 | 快速找到想看的模型 | 18 张模型卡、主题筛选、关键词搜索、我的收藏进度 |
| 单件展柜 | 沉浸式看模型 | 3D 模型、语义机位、观察点、展签、收藏、前后展品 |
| 我的藏册 | 留下个人完成感 | 已看展品、收藏印记、分享藏册卡 |

所有页面保持独立可分享链接，例如 `museum.html?item=canton-tower`。分享链接直接进入对应展品，提供“回到展览”入口；浏览器前进/返回仍然符合预期。

## 四、主旅程与交互

### 1. 首次入馆

1. 首屏使用大幅留白和展品剪影/预览图，标题只说清楚“这是一座可以旋转阅读的广州模型博物馆”。
2. 主按钮“开始看展”进入当期策展；次按钮“浏览全部 18 件”直接进入长廊。
3. 可有一次轻量揭幕：预览轮廓淡入、印章落下、主标题出现，总时长控制在约 1.2 秒；用户滚动、点按或开启减少动态模式时立即结束。
4. 音效默认关闭，首次打开不自动播放声音，不强制全屏，也不把教程挡在模型前。

### 2. 展品长廊

- 用已有 `refs/preview/preview-overview.png` 作为卡片主视觉，不在长廊同时运行 18 个 WebGL 场景。
- 每张卡显示展品编号、名称、所属主题、一个 20 字左右看点，以及“已看”印记；主视觉保证模型图占卡片面积的一半以上。
- 手机上用两列卡片，主展品横跨两列；桌面端用疏密有致的展柜网格。点击卡片明确进入展品页。
- 顶部主题条与搜索可组合使用；搜索覆盖名称、别名、主题和看点。没有结果时提供清除筛选入口。
- 可策展 3–4 条“观看序列”，每条 4–6 件展品，例如“屋檐与街巷”“城中的信仰”“新城的几何”“山水入城”。这些是线上观展顺序，不暗示地理路线或历史先后。

### 3. 单件展柜

**首屏布局：**模型首先进入视野，名称、编号、简短展签和关闭/返回入口轻量浮在边缘；不让长文、地图或按钮压住模型。

- 桌面端：主模型占据约 70% 画面；侧栏容纳展签与观察点。底部展示总览、正面、细节等语义机位。
- 手机端：模型优先占据首屏约 58–66% 高度；底部是可拖动的展签抽屉，初始只露出标题、看点和“观察细节”入口。向上展开后阅读事实、热点和来源。
- 第一次进入先落在总览机位。画面提示“拖动旋转 · 双指缩放”，提示数秒后消失；之后保持自由交互。
- 机位按钮使用内容语言，例如“总览 / 屋脊 / 院落”，点击后平滑移动到已有 preset；切换机位时同步只显示相关热点，其他热点淡出。
- 热点避免常驻堆叠：默认总览最多显示 3 个简洁标记；其余放在“观察点”列表。点击列表项时相机移近、热点高亮、展签切到对应说明。用户点击模型可关闭当前说明并恢复自由旋转。
- 控件包括：重置视角、收藏/已看、上一件/下一件。前后切换由明确按钮触发；在模型画布内不使用横滑换展，避免和旋转手势冲突。
- 当前展品显示“第 03 / 18 件”及轻量进度线。切换默认不自动跳转，不替用户做决定。

### 4. 展览结束与个人印记

观看过展品后生成本地“藏册”：按主题展示已看数量和对应印章，可随时重新打开模型。完成一条策展序列时展示“本篇看完”，给出“再看一个相关展品 / 回长廊”两种清楚选择。

每件展品可生成分享卡：使用已有预览图，加上编号、标题、用户选中的一句看点和印章。先支持保存图片/系统分享；分享卡注明“风格化模型”。收藏进度优先存本机，不要求登录。与现有图鉴的“去过”状态保持兼容，不把“线上看过”自动等同于现实到访。

## 五、主题策展与内容例子

主题是编辑标签，允许交叉归属；不是行政区或路线。

| 主题 | 可纳入的模型例子 |
|---|---|
| 屋檐与街巷 | 陈家祠、永庆坊、上下九、沙面、北京路 |
| 城中的信仰 | 光孝寺、六榕寺、石室圣心大教堂、粤剧艺术博物馆 |
| 新城的几何 | 广州塔、广州大剧院、广东省博物馆、中山纪念堂 |
| 山水入城 | 白云山·摩星岭、云台花园、越秀公园、荔枝湾 |
| 城市记忆 | 南越王博物院、北京路、陈家祠、沙面等，可与其他主题交叉 |

主题名单只是第一版策展建议，最终归属由编辑确认；不按模型坐标推算顺序。

**陈家祠单件示例：**进入后先看总览展签“先看整体院落，再找屋脊上的岭南工艺”；三个快捷观察入口是“正立面 / 屋脊陶塑 / 青云巷”。点“屋脊陶塑”后移到 detail 机位，只留相应标签，并出现短说明和来源入口。读完可切到下一件展品“永庆坊”，也可回到长廊。示例文案需要校对现有模型视角、数据卡和来源，未知尺寸不进入展签。

## 六、视觉与动效方向

### 视觉关键词

**纸本档案、私人收藏、当代美术馆、岭南朱印。**优先延展现有展柜的暖纸色、黑墨色和朱红印章，配少量青绿/铜金作为主题提示。模型继续在克制的中性光环境中呈现，界面留白，避免每件展品重新换一套灯光或主题。

- 字体层级：展名用宋体/衬线建立文化气质；正文和控制使用清晰的无衬线；编号、英文小字承担档案标签感。
- 组件语言：窄边线、细编号、展签、印章、纸张纹理；纹理只做轻微点缀，保证手机低端屏幕可读。
- 颜色：暖白/浅石色作为底；墨色文字；朱红作为唯一强操作强调色；青绿用于主题或已看状态。
- 参考成熟体验模式：借鉴 Apple 产品叙事的“单件聚焦、逐步揭示细节”，以及 Google Arts & Culture 数字展览的“主题策展、展签与观看序列”。吸收其信息节奏，不复制界面。

### 动效节奏

- 序厅入场：淡入、轻微景深/光晕变化，1 秒左右；可跳过。
- 进入展品：预览图先出现，模型加载完成后交叉淡化到实时 3D；不展示空白 canvas。
- 切机位：约 450–700 ms 的缓动运镜，支持再次点按中断并立刻响应。
- 展签抽屉：跟手拖动，停靠在预览、半开、展开三档；滚动正文与拖动抽屉有明确手势区域。
- 已看印记：一次简短盖章反馈；不循环、不闪烁、不持续自动旋转。

## 七、数据与工程落地

### 数据组织

新增独立的 `museum-catalog.json`（或 `museum-catalog.js`）管理策展内容，不把展览分类混入现有地图数据。每条展品引用已有 `spot.json` 的 `id`，复用名称、机位、热点、来源和预览图路径；展览数据只补：主题标签、展签短文、序列排序、推荐观察点和分享文案。

字段建议：

```json
{
  "id": "opera-house",
  "themes": ["new-form", "city-memory"],
  "edition": "03",
  "lead": "两块没有直角的砾石，把剧场变成一件可以绕行观看的雕塑。",
  "cover": "../content/spots/opera-house/refs/preview/preview-overview.png",
  "storyOrder": ["facade", "mouth", "pool"],
  "sequenceIds": ["gd-museum", "canton-tower"]
}
```

序列顺序由编辑维护，不从经纬度或城市路线自动生成。`spot.json` 的 `status` 当前仍可能是 `draft`，不能直接作为线上展出状态；是否纳入首发由独立展览清单明确控制。

### 页面与复用

- 新增独立 `museum.html` + `museum.css` + `museum.js`，初期不重写 `spot.html` 渲染器。
- 长廊只加载轻量展览数据与静态预览图；用户打开展品后，才加载 `spot.html?id=<id>&embed=1&from=museum` 及对应模型。
- 页面只保持一个有效 3D 上下文。关闭展品或切换模型时先释放前一个 iframe/模型资源；切换期间用目标展品预览图填充，加载成功后替换。
- `spot.html` 继续作为独立可分享展品页；如需宿主控制器，可新增受限的 postMessage 命令，如请求机位、收藏状态同步、关闭展品，并校验 `origin` 与展品 id。
- 分享链接应支持直接进入展品和机位；收集状态保存在本机 `localStorage`，并兼容现有 `canton-atlas-marks` 读写约定。

## 八、首发范围与实施顺序

### MVP（先发布可用版本）

1. 独立博物馆首页、主题长廊、关键词搜索、18 个展品卡片与直接链接。
2. 单件展柜复用现有模型页，手机布局改为模型主视野 + 底部展签抽屉。
3. 展签观察点从现有 hotspots/presets 生成，逐件补充一段编辑后的主文案。
4. 已看状态、主题序列进度、前后展品、回长廊和基础分享链接。
5. 统一视觉系统、首屏加载占位、静态模型降级、返回/异常状态。

### 第二阶段

- 个人藏册与高清分享卡；策展序列的章节转场和完成印章；收藏夹同步选项。
- 主题章节封面、模型局部对照、更多来源展开方式。
- 只在完成真机性能验证后，评估额外的粒子、环境声、夜间展厅或多展品 3D 序厅。

## 九、验收标准

- 用户 5 秒内能理解这是“广州地标 3D 模型展览”，无需先读长说明。
- 首屏首先显示可见展览内容；长廊未打开模型时不创建 WebGL 场景。
- 展品页有静态图、骨架屏、失败重试和返回入口；模型加载失败不会困住用户。
- 任意 18 件展品都能从卡片打开，直接链接可复现，浏览器返回逻辑正常。
- 手机 320–430px 宽度无横向滚动；常用触控区至少 44px；安全区、低横屏、系统手势均通过真机验收。
- 模型只在画布区域响应旋转，展签滚动不带动相机；双指缩放与系统页面缩放冲突经过真机检查。
- 中端手机达到可接受的稳定帧率；切换展品后前一模型的资源释放，连续看 10 件没有明显内存增长。具体首屏和帧率指标以目标设备测量后定档。
- 支持减少动态效果；键盘可操作主要控件；静态预览可替代 3D；文字与背景对比度达标。
- “模型示意”常驻可发现；不显示未知尺寸、推导路线或未经核实的地理关系。
- “线上看过”和“现实去过”使用不同状态，避免串写现有到访记录。

## 十、实施建议

第一步先做 **一页完整可点击的 H5 视觉原型**：序厅、长廊、单件展柜、底部抽屉和分享卡五个关键状态，以广州大剧院或广州塔作为样板，陈家祠作为传统工艺样板。原型确认信息密度、切换手感和展签气质后，再接入全部 18 件。

首版最值得投入的设计资源是：模型首屏构图、切机位运镜、展签排版、移动端底部抽屉与内容编辑。新建一个宏大的多人多模型 3D 场景、复杂粒子、背景音乐和地图联动都不属于首发必要条件。
