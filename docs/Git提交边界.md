# Git 提交边界（2026-11-03）

## 可提交
- 网页与模型源码、景点数据卡、开发工具、测试、CI配置。
- 项目生成且不含参考照片的模型剪影、模型预览图。
- 文档与来源说明（不要写入凭据、个人信息或未经授权的照片）。

## 只保留本地
- `.local/`、`.env` 与 `.env.*`：开发/生产凭据。
- 根目录 `高德3d地图案例.html`：已确认含 Key 参数；不复制到源码或发布产物。
- 根目录名称含“近景”的文件夹：历史大体积验收附件；同名 Markdown 记录仍可提交。
- 所有景点 `refs/overlay/` 下 `reference-*`、`rough-*`、`overlay-*`：内部参考照片或含照片的叠图结果。模型自身 `*-silhouette.png` 和 `SOURCE.md` 不受此排除影响。
- 历史 `canton-atlas/dist/`。

## 每次提交前
1. 查看 `git status --short` 和 `git diff --stat`，只暂存本次任务文件，避免直接全量添加。
2. 用 `git diff --cached --name-only` 检查即将提交的路径；再在本机审阅差异，不把凭据内容粘贴到聊天或日志。
3. 运行 `npm test`；新增的 Git 边界测试会检查排除规则和索引，能发现用 `git add -f` 强制添加的已忽略文件。
4. 新照片或新敏感文件如果不符合现有命名约定，应放 `.local/`，或先增加精确排除规则。不要认为所有 JPG/PNG 都安全，也不要将所有图片一律排除。

## 本轮检查边界
恢复上述排除规则；未删除/移动任何本地素材，未更改业务代码，未发布或推送。
当前 Git 索引没有匹配排除规则的文件，内部参考照片和高德示例未被跟踪。
测试是路径保护，不是全面的凭据扫描；凭据若被改名写入普通源码仍需人工审阅。Git忽略规则也不是网站访问控制或发布打包规则，部署时仍必须明确选取运行时文件，不能全量上传整个工作区。
本轮未扫描远端和历史提交；如果凭据曾经外泄，需要停用/轮换，不能只靠添加gitignore。
